Understanding LoRA and QLoRA for LLM Fine-tuning

The world of Large Language Models (LLMs) is rapidly evolving, and with their immense power comes an equally immense appetite for computational resources.

August 1, 2025 / 8 min read Read on Substack ↗

The world of Large Language Models (LLMs) is rapidly evolving, and with their immense power comes an equally immense appetite for computational resources. Fine-tuning these behemoths to adapt them to specific tasks or domains is crucial for real-world applications. However, traditional fine-tuning methods often demand an impractical amount of hardware. This is where Parameter-Efficient Fine-Tuning (PEFT) techniques, specifically LoRA (Low-Rank Adaptation) and QLoRA (Quantized Low-Rank Adaptation), come into play, offering a revolutionary approach to efficient LLM customisation.

The Challenge of Full Fine-Tuning

Before diving into LoRA, let's understand the conventional approach: full fine-tuning. This method involves updating all the parameters within a pre-trained LLM. While effective, it requires significant computational resources, including numerous heavy-duty GPUs, which are typically beyond the reach of a normal consumer or developer. Imagine a large matrix 'W' representing all the weights of a deep neural network within an LLM – full fine-tuning means modifying every single value in this colossal matrix.

To address this, PEFT emerged. Instead of updating all the weights in a large matrix, PEFT focuses on updating only a small subset of the weights, making the process computationally efficient. Among PEFT techniques, LoRA stands out as one of the most important and efficient.

Essential Concepts for Understanding LoRA

To truly grasp LoRA, we first need to understand two fundamental mathematical concepts:

  1. Rank of a Matrix: The rank of a matrix fundamentally represents the dimensionality of the vector space spanned by its rows or columns. More simply, it tells us how many rows or columns are linearly independent.

    • Consider Matrix A: 

                                 | 1  2 |
                           | 3  6 |

      Here, the second row [3 , 6] can be represented as three times the first row [1 , 2](i.e., 3×[1 , 2]), meaning it's not linearly independent of the first row. Thus, the rank of Matrix A is 1.

    • Now, consider Matrix B: 

                                | 2  1  3 |
                          | 4  2  1 |
                          | 1  5  2 |

      Here B is a 3x3 matrix where all columns and rows are linearly independent. None of its rows or columns can be represented using the others. In such a case, the rank of Matrix B would be 3.

    • Another example, Matrix C: 

                                 | 1  2 |
                           | 3  4 |

      The rank of this 2x2 matrix is 2, as its rows and columns are linearly independent.

  2. Matrix Decomposition: Matrix decomposition is the process of breaking down a matrix into simpler matrices that are easier to analyse, compute, or interpret. It's widely used in machine learning, computer vision, and specifically forms the actual technique behind LoRA. By definition, it involves breaking down a matrix into a product of simpler matrices.

    • For instance, a large 4x4 matrix 'W' can be split into two smaller matrices: Matrix A (4x1) and Matrix B (1x4). The magic lies in the fact that when you perform a dot product of Matrix A and Matrix B, the result is the original 4x4 Matrix W. This means instead of working on the whole original weight matrix, we can decompose it into these two smaller matrices and perform operations on them.

LoRA: Low-Rank Adaptation

LoRA is a parameter-efficient fine-tuning method that makes model adaptation both fast and memory-efficient.

The Core Idea: Instead of directly modifying the enormous pre-trained model weights (W), LoRA injects small, trainable low-rank matrices into specific layers of the model. The original pre-trained weights remain frozen.

Let's break down its mathematical application step-by-step:

  1. Start with the Original Weight (W): You begin with the original, pre-trained weight matrix (W) from your LLM (e.g., a Llama model).

  2. Adding a New Weight (ΔW): To adapt the model to new data (e.g., your hotel's specific information), LoRA conceptualises a new, fine-tuned weight matrix (W(new)​) by adding a modification ΔW to the original weight : 

                         W(new​) = W(original)​ + ΔW

  3. Decomposition of ΔW: This is where LoRA comes. Instead of directly training or working with the large ΔW, it is decomposed into two much smaller, low-rank matrices: Matrix A and Matrix B. 

                                ΔW = A × B

    If W is a D x K matrix, Matrix A will have dimensions D x r, and Matrix B will have dimensions r x K, where 'r' is the low rank (a very small number, e.g., 4). The multiplication of A (D x r) and B (r x K) correctly yields a D x K matrix for ΔW.

  4. Operations on A and B: All the training operations are performed exclusively on these smaller matrices, A and B, not on the full ΔW or W. After training, A and B are multiplied, and their product (ΔW) is added to the original W to get W(new​).

  5. Injection into Transformer Architecture: In Transformer models, the attention mechanism relies on Query (WQ), Key (WK), and Value (WV) matrices. LoRA modifies these by adding the decomposed ΔW (i.e., A*B) to each:

                        WQ(modified​) = WQ + AQ × BQ
                    WK(modified​) = WK + AK × BK                                                                                                                    
                    WV(modified​) = WV + AV × BV

    (Note: AQ, BQ, AK, BK, AV, BV are the specific decomposed matrices for each respective attention layer). During inference, these modified values are used.

The Mathematical Efficiency of LoRA

Let's quantify the parameter reduction using an example from the source:

  • Consider a large LLM weight matrix W with dimensions D = 4096 and K = 4096.

  • Full Fine-Tuning: If you were to update all weights in this matrix, the total trainable parameters would be D * K = 4096 * 4096 = 16,777,216 (approximately 16.7 million).

  • LoRA Fine-Tuning: Now, let's apply LoRA with a rank (r) of 4.

    • Matrix A dimension: D x r = 4096 x 4.

    • Matrix B dimension: r x K = 4 x 4096.

    • The total trainable parameters for LoRA would be (D * r) + (r * K) = (4096 * 4) + (4 * 4096) = 16384 + 16384 = 32,768 (approximately 32k). This demonstrates a reduction factor of almost 10^3 (from 16.7 million to 32k). It's crucial to understand that increasing the rank (r) will significantly increase the total number of trainable parameters.

Benefits of LoRA:

  • Requires substantially less memory.

  • Enables much quicker model training.

  • Makes it possible to fine-tune LLMs on less powerful hardware, such as a normal laptop .

  • LoRA effectively preserves the model's pre-trained knowledge.

QLoRA: Quantized Low-Rank Adaptation for Even Greater Efficiency

QLoRA is an extension of LoRA that pushes memory efficiency even further by combining LoRA with quantization.

The Core Idea: While LoRA reduces the number of trainable parameters, QLoRA reduces the memory footprint of the base model weights themselves by quantizing them.

Here's how QLoRA operates:

  1. LoRA Foundation: QLoRA is built upon the LoRA technique, meaning it still uses the efficient low-rank adaptation matrices (A and B) for fine-tuning.

  2. Quantization of the Base Model: The key additional step is to quantize the base (pre-trained) model weights to a lower bit-precision, typically 4-bit.

  3. What is Quantization ?

    Quantization is a process of reducing the memory space a number or data type occupies. For example, a number that typically occupies 8 bytes of space might be quantized to occupy only 1 byte. This means a large model (e.g., 1GB) could be reduced to a much smaller size (e.g., 600MB) through quantization.

Mathematical Details of Quantization (Precision vs. Memory):

  • Float 32 (FP32): This data type uses 32 bits of memory to store a number (e.g., 1.23456789). Internally, it allocates 1 bit for the sign, 8 bits for the exponent, and 23 bits for the fraction.

  • Float 16 (FP16): This data type uses 16 bits of memory, significantly reducing memory allocation. However, it loses precision (e.g., 1.235). Internally, it allocates 1 bit for the sign, 5 bits for the exponent, and 10 bits for the fraction.

  • The transition from FP32 to FP16 can result in a 50% reduction in memory space.

  1. Applying Quantization in QLoRA: In QLoRA, the low-rank matrices (A and B) from LoRA contain floating-point weights and are kept in full or mixed precision to maintain training stability. Only the base model weights (W) are quantized to 4-bit precision, significantly reducing memory usage. This quantization improves efficiency but may lead to slight precision loss

    (e.g., a value like 1.24567 might become 1.24).

Trade-offs with QLoRA:

While quantization offers substantial memory reduction, it's vital to acknowledge that it involves losing precision. The decision to use QLoRA (and thus accept this precision loss) depends on the specific use case, data type, and scenario. There are instances where maintaining full precision is paramount.

In essence, LoRA streamlines fine-tuning by dramatically reducing the number of trainable parameters through clever low-rank matrix decomposition. QLoRA takes this efficiency a step further by also reducing the memory footprint of the model's weights themselves through quantization, enabling even greater memory savings.

Both techniques are pivotal in making the customisation of powerful LLMs more accessible and efficient for a wider range of applications and hardware setups. They represent a significant leap towards democratising access to advanced AI capabilities.
